# SopDungeons

## Плавный спавн и переходы

Параметр `spawn-interval-ticks` хранится отдельно в каждой группе мобов внутри `dungeons.yml`. По умолчанию моб появляется каждые 10 тиков, а значение `0` включает мгновенное появление всей группы. В командах это последний необязательный аргумент.

Параметры `transitions.fade-before-ticks` и `fade-after-ticks` управляют затемнением вокруг телепорта. После прибытия игрок не получает урон до `invulnerability.duration-ticks` тиков или до первого перемещения, если включен `until-first-movement`. Поворот камеры защиту не снимает.

## Область входа

Выделите область через WorldEdit или команды `/sd pos1` и `/sd pos2`, затем выполните `/sd entrance-area <id>`. Когда игрок с правом `sopdungeons.use` пересекает границу области, плагин автоматически отправляет его в подземелье. Вход использует то же затемнение и временное бессмертие, что переходы между этажами. Удалить область можно командой `/sd entrance-area <id> clear`.

SopDungeons отвечает только за геометрию подземелий, отдельные миры, переходы между этажами и открытие лестницы после босса. Группы, NPC, ключи, порталы, спавн мобов и награды остаются внешним плагинам.

## Режимы

- `STATIC` - общий постоянный мир, все этажи открыты.
- `TEMPLATE` - отдельная сессия-копия подготовленного мира из `plugins/SopDungeons/templates/<name>`.
- `GENERATED` - постоянный отдельный пустой мир, в котором WorldEdit/FAWE один раз собирает подземелье.

## Быстрая настройка STATIC или TEMPLATE

```text
/sd create crypt STATIC
/sd world crypt dungeon_world
/sd entrance crypt
/sd exit crypt

/sd floor add crypt 1
/sd pos1
/sd pos2
/sd floor bounds crypt 1
/sd floor up crypt 1
/sd floor down crypt 1
/sd floor arrivalup crypt 1
/sd floor arrivaldown crypt 1
```

Если установлен WorldEdit, команды областей сначала используют его текущее выделение. Без WorldEdit используются `/sd pos1` и `/sd pos2`.

Для новых настроек удобнее использовать понятные имена: `/sd floor entrance <id> <n>` задает вход этажа при спуске сверху, а `/sd floor return <id> <n>` задает точку возврата при подъеме снизу. Старые `arrivalup` и `arrivaldown` также поддерживаются. Если задана только одна точка, она используется как запасная в обоих направлениях.

Для `TEMPLATE` вместо `world` задается `/sd template crypt <folder>`. Координаты входа и этажей настраиваются в заранее загруженной исходной карте, а затем папка карты помещается в `plugins/SopDungeons/templates`.

Привязка босса EliteMobs к этажу:

```text
/sd floor boss crypt 1 custom_boss_file.yml
```

После смерти этого босса следующий этаж открывается навсегда до завершения данной сессии. Этаж без босса открывает следующий автоматически.

## Генерируемые подземелья

Выделите готовую комнату и сохраните ее:

```text
/sd module save entrance ENTRANCE
/sd module save corridor NORMAL
/sd module save elite_room ELITE
/sd module save floor_boss BOSS
/sd module save stairs_up STAIRS_UP
/sd module save stairs_down STAIRS_DOWN
/sd module save transition TRANSITION
/sd module save finish EXIT
```

Все MODULES-схемы используют единый квадратный размер из `generation.modules.size`, а их высота может быть любой. Размер должен быть нечётным и не меньше `5`; встроенные схемы рассчитаны на `15×15`. Горизонтальная позиция коннектора автоматически определяется полем `direction`: край соответствующей стороны и центральный блок этой грани. В `modules.yml` для коннектора настраивается только уровень ног `y`; поля `x` и `z` не используются. Вес, минимальная глубина, допустимые вращения и `boss` для BOSS-модуля также редактируются в `modules.yml`. Дополнительные `GENERIC`-коннекторы создают боковые ответвления с модулями типа `DEAD_END`.

Origin схемы при загрузке автоматически приводится к её минимальному углу. Поэтому положение игрока во время `//copy` не влияет на размещение импортированной схемы.

Каждый модуль может содержать секцию `spawns` с относительными `x`, `y`, `z`, провайдером `VANILLA` или `ELITEMOBS`, ID моба, количеством, радиусом и настройками респавна. Запись с `boss: true` становится боссом этажа и после смерти открывает следующий этаж. BOSS-комната без такой записи не блокирует лестницу.

```text
/sd create random_crypt GENERATED
/sd exit random_crypt
/sd generation random_crypt 3 12 true CATACOMBS
/sd natural random_crypt false
/sd enter random_crypt Player1 Player2
```

`GENERATED` требует WorldEdit или FAWE. Остальные режимы работают без них.
Аргумент `bosses` включает или отключает босса. В режиме `MODULES` включайте его только если BOSS-модуль содержит секцию `spawns` с `boss: true`; в режиме `CATACOMBS` босс берётся из `generation.catacombs.boss`.

Режим `CATACOMBS` создаёт через FAWE полноценный DFS-лабиринт с широкими коридорами, тупиками, редкими циклами и указанным количеством комнат. Коридоры получают узорчатые полы, состаренные стены и потолочное освещение, а весь этаж закрывается дополнительной оболочкой со всех шести сторон. Западная лестница ведёт вверх к предыдущему этажу или выходу, восточная лестница уходит вниз к следующему этажу; на последнем этаже её заменяет магический круг возвращения. Перед выходом гарантированно создаётся золотая комната босса. В GENERATED-мире отключены смена времени, погода и весь ванильный естественный спавн; время задаётся через `generation.generated-world.time`. Для этого режима обязателен FastAsyncWorldEdit; обычный WorldEdit намеренно не используется, чтобы не блокировать сервер при постановке миллионов блоков. `MODULES` оставляет генерацию из схем.

Команда `generation` автоматически начинает первоначальное построение. Дождитесь сообщения о готовности перед `/sd enter`. Команда `/sd prepare <id>` загружает уже существующий GENERATED-мир либо создаёт его, если подземелье ещё не генерировалось. Повторные входы не перестраивают карту.

Повороты строятся из модулей, у которых направления `ENTRY` и `EXIT` не противоположны. `GENERIC`-коннекторы создают боковые ответвления с модулями типа `DEAD_END`. Генератор заранее проверяет пересечения и при конфликте подбирает другую комнату или ориентацию.

Режим `MODULES` заполняет прямоугольную сетку и вырезает в ней классический DFS-лабиринт: с длинным основным маршрутом, поворотами, развилками, тупиками и редкими дополнительными циклами. Затем каждая отдельная неперекрывающаяся клетка `15×15` получает схему точной формы: прямой коридор, угол, T-развилку, перекрёсток, комнату или тупик. Начало этажа получает модуль лестницы вверх, дальний конец промежуточного этажа — лестницу вниз, а последний этаж завершается модулем `return_portal` из схемы `maze_return_portal.schem`. Лестничные и финальный модули являются тупиковыми и используют только один коннектор `inside`; переход срабатывает сразу при входе в лестницу, а выход — в центре магического круга. Размер задают `generation.modules.minimum-cells` и `cells-per-room`, частоту циклов — `loop-chance`. Перед вставкой схем весь объём послойно заполняется `envelope-material`, поэтому лабиринт со всех сторон закрыт породой.

Перед заливкой оболочки и вставкой схем генератор асинхронно подготавливает затрагиваемые чанки через Paper API и удерживает их plugin tickets до завершения этажа. Параллелизм и таймаут задаются в `generation.chunk-preparation`; это предотвращает синхронное ожидание генерации и освещения чанков внутри операции FAWE. Если сервер не предоставляет асинхронный API Paper, генерация завершается ошибкой вместо блокировки главного потока.

Мобы, созданные SopDungeons, помечаются отдельно и проверяются настройками `mobs.despawn`. Обычные мобы удаляются, если рядом на том же этаже нет участника забега, и не появляются заново до приближения игрока. По умолчанию радиус равен 48 блокам, проверка выполняется раз в 20 тиков, а боссы не деспавнятся до завершения сессии.

Присутствие игрока отслеживается по миру и границам этажей. Телепорт через `/spawn`, смена мира, выход пешком за общую территорию этажей или отключение от сервера автоматически удаляют игрока из сессии. Внешний телепорт не заменяется настроенной точкой `exit`; она используется только при явном выходе через SopDungeons.

GENERATED-мир, его этажи, переходы и спавны сохраняются в `dungeons.yml` и существуют между перезапусками сервера. Пустой мир не удаляется по таймауту. Удаление выполняется только через `/sd delete <id>`.

Стандартный набор модулей упакован в JAR. При первом запуске схемы автоматически извлекаются в `plugins/SopDungeons/modules`, а пустой `modules.yml` заполняется их описаниями. Существующие схемы и непустой пользовательский конфиг не перезаписываются.

## API

API регистрируется через Bukkit Services Manager:

```java
SopDungeonsApi api = Bukkit.getServicesManager()
        .load(SopDungeonsApi.class);

api.start("crypt", playerIds);
```

Доступны запуск и остановка сессии, выход игрока, ручное открытие следующего этажа и поиск сессии. Асинхронные вызовы `start` и `stop` автоматически возвращаются в серверный поток; синхронные методы изменения состояния должны вызываться в главном потоке Bukkit.

Плагин публикует `DungeonSessionStartEvent`, `DungeonSessionEndEvent`, `DungeonPlayerEnterEvent`, `DungeonPlayerLeaveEvent`, `DungeonFloorUnlockEvent` и `DungeonModulePasteEvent`. Последнее событие сообщает внешнему плагину мобов ID сессии, ID и тип вставленной комнаты, мир, этаж и ее границы.

Для диагностики используйте `/sd info <id>` и `/sd sessions`.

## Временные миры

Только пустая TEMPLATE-сессия закрывается через `empty-session-timeout-seconds`, после чего её клонированный мир удаляется. GENERATED-миры считаются постоянными и при запуске загружаются из сохранённого определения.

## Мобы EliteMobs

SopDungeons управляет точками, количеством и повторным появлением мобов. Характеристики, способности и предметы задаются в конфигурации EliteMobs.

Чтобы запретить естественный ванильный спавн только внутри границ этажей, не затрагивая остальной мир:

```text
/sd natural crypt false
```

Встаньте в центре будущей группы и добавьте точку:

```text
/sd floor spawn crypt 1 add skeletons crypt_skeleton.yml 5 4 WHEN_CLEARED 30 false
```

Аргументы после ID моба: количество, радиус, режим возрождения, задержка в секундах и признак босса.

- `NEVER` - группа появляется один раз за сессию.
- `WHEN_CLEARED` - вся волна появляется заново только после убийства последнего моба.
- `AFTER_DELAY` - через задержку восполняются недостающие мобы, даже если часть группы еще жива.

Босс первого этажа:

```text
/sd floor spawn crypt 1 add guardian crypt_guardian.yml 1 0 NEVER 0 true
```

Для точки с `boss: true` количество принудительно равно одному, а ID автоматически становится ключом открытия следующего этажа. Посмотреть или удалить точки:

```text
/sd floor spawn crypt 1 list
/sd floor spawn crypt 1 remove skeletons
```

Волна активируется, когда хотя бы один участник сессии находится внутри `bounds` этажа. Созданные сущности помечаются плагином и удаляются при завершении временной сессии, удалении точки или перезапуске сервера.

### Спавн вокруг игроков

Этот режим поддерживает отдельное количество мобов для каждого игрока на этаже:

```text
/sd floor spawn crypt 1 add-around ambient crypt_skeleton.yml 3 12 28 20 10
```

После ID моба указываются: количество на игрока, минимальный радиус, максимальный радиус и задержка восполнения в секундах. В примере для каждого участника поддерживается до трех скелетов на расстоянии от 12 до 28 блоков.

Плагин делает до 48 попыток найти позицию внутри `bounds` этажа. Подходящая позиция должна находиться в уже загруженном чанке, иметь твердый блок снизу, не содержать жидкость и не быть ближе минимального радиуса к любому участнику. Координаты ставятся в центр блока (`x + 0.5`, `z + 0.5`). После создания проверяется фактический `BoundingBox` моба: при пересечении с коллизией блока сущность удаляется и выбирается другая точка. Когда игрок покидает этаж, закрепленные за его квотой сущности удаляются.
